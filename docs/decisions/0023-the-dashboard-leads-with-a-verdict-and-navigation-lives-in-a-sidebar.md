# The dashboard leads with a verdict, and navigation lives in a sidebar

_Recorded 2026-11._

The dashboard opens with a status panel that answers "is anything wrong?" before showing any chart. `RailsPulse::Dashboard::Verdict` combines the per-area counts from `HealthSummary` with the `NeedsAttention` list the page already loads, runs no queries of its own, and lets the worst state anywhere set the overall state: one critical area or critical attention item makes the whole panel "Action needed". The headline names the problem ("9 exceptions firing") when there are one or two, and counts by severity ("5 critical and 5 warnings") above that, because naming every problem ran to several lines on a busy app. The panel offers one next step: review the Needs Attention list when it has entries, otherwise open the worst area's page. Needs Attention sits directly beneath it and collapses to a single line when empty; metrics and charts follow, with Deployments and Storage in a narrow side column because they are reference information rather than the answer.

Navigation moved from the top bar to a left sidebar. The top bar had run out of room as sections were added and already collapsed into the menu button below 1280px; a sidebar takes more sections without crowding the time range and filters, and leaves the top bar for the page title and controls. Below the same 1280px breakpoint the sidebar is hidden and the existing menu sheet is used. The sidebar collapses to an icon rail, and a "TUI" toggle swaps the look to a terminal style; both choices are kept in `localStorage` and restored by the inline script in the layout before first paint, the same way the colour scheme is, so the page never renders one way and then snaps to the other.

The alternatives were to keep the row of health badges above the metrics, which still made the reader add up four badges to reach a verdict, and to keep the existing page and only restyle it, which several design prototypes did without changing what the page helps someone decide. The cost is a larger stylesheet under `app/assets/stylesheets/rails_pulse/theme/`, a layout that every page shares and so changes every page at once, and two more client-side preferences that live per browser and are not shared across a team.
